## 摘要

1. **原始单位字段极脏**：89,477 个去重取值，但 **124 个就覆盖 99% 的金额**，长尾 89,353 个合计只有 1%。
2. **机械归一化几乎无效**：大小写 + 全角半角 + 去空白四级处理，只折叠掉 2.3% 的取值。真正有用的是**按量纲人工建映射表**。
3. **量纲映射成功**：89,477 → **32 个规范单位**。折算后的单价能对上真实市场价（铜 51.99 元/kg、钢筋 4.21 元/kg、电 0.84 元/kWh）。
4. **效果显著但未彻底**：产品内主导单位占比中位数从 0.504 升到 0.731（金额加权 0.836）；"只留主导单位"的损失从 30% 降到 16%。
5. **残余分散不是拼写问题**：主导量纲占比 ≈ 主导单位占比（0.842 vs 0.836），说明同义词已经合并到头，继续加映射不会再有收益。
6. **量纲之间差异巨大**：质量/能量/体积类价格离散度 2–14 倍，可用；**计数/成套/未知类 269–348 倍，不可比**，而这三类占 42% 的金额。
7. **★ 附带发现一个更严重的问题**：`Σ金额/Σ数量` 构造的市场价，在 **36% 的金额上低于该市场 90% 企业的实际成交价**，被极端数量污染。这直接影响 `p_mkt` 和买卖方 LOO。

## 2 原始单位字段有多脏

### 2.1 规模与金额覆盖

去重取值 **89,477 个**，最长 48 字节。但金额高度集中：

| 覆盖金额 | 需要多少个单位 |
|---|---|
| 50% | **3** |
| 80% | **11** |
| 90% | 25 |
| 95% | 43 |
| **99%** | **124** |
| 99.9% | 476 |

**这是整个方案可行的前提**：人工审一张 124 行的映射表就够，剩下 89,353 个长尾归 `OTHER` 只影响 1% 的金额。

金额前 10（买卖合并）：`吨` 39.6% ／ `个` 9.9% ／ `UNKNOWN` 9.8% ／ `台` 7.4% ／ `套` 3.2% ／ `件` 3.0% ／ `公斤` 2.0% ／ `辆` 1.7% ／ `只` 1.5% ／ `千克` 1.4%。

### 2.2 同一概念被拆成几百种拼法

| 概念 | 不同拼法的取值数 |
|---|---|
| `kg` / `千克` / `公斤` 开头 | **230** |
| 含"吨" | **319** |
| 含"个" | **853** |

`公斤`(2.04%) + `千克`(1.41%) + `kg`(0.83%) + `KG`(0.81%) 合计 5.09% 的金额，却散在四个取值里；再加 `吨`(39.6%)、`克`(0.31%)，**质量家族共占 45.2% 的金额**。

### 2.3 机械归一化几乎没用

| 归一化层级 | 去重取值数 |
|---|---|
| L0 原始（已 trim） | 89,477 |
| L2 + 去所有空白 | 88,971 |
| L3 + `upper` | 87,760 |
| L4 + NFKC 全角转半角 | 87,444 |

四级处理**只折叠掉 2,033 个（2.3%）**。结论是：不能指望正则规则，必须按语义建映射表。
（但 `upper` 把 `kg`+`KG` 合并这一条本身值 1.6% 的金额，虽然只少 1 个取值也不能省。）

## 3 单位映射表设计（`unit_map.csv`）

对覆盖 99% 金额的 124 个单位逐个分量纲，落成可审核的 CSV：

```
rank, raw_unit, share_pct, dimension, base_unit, factor, confidence, note
```

### 3.1 可换算量纲 —— 折算到基准单位

| 量纲 | 基准 | 主要成员与系数 |
|---|---|---|
| MASS | **千克** | 吨/T/t/MT/吨(MT)/千公斤 ×1000，公斤/千克/kg/KG/Kg ×1，克 ×0.001，斤 ×0.5 |
| COUNT | **个** | 个/台/件/只/条/支/片/张/块/根/把/粒/枚/本/册/部/架/樘/PCS/EA/PC/Each ×1，双 ×2，千个/千只 ×1000，万支/万只/万张 ×10000 |
| ENERGY | **千瓦时** | 千瓦时/度/kWh/KWH/kW.h/kW·h ×1，千度/千千瓦时/兆瓦时/MW.H ×1000，万度/万千瓦时 ×10000，吉焦 ×277.78 |
| LENGTH | **千米** | 千米/公里/KM ×1，米/m/M ×0.001，码 ×0.0009144 |
| VOLUME | **立方米** | 立方米/立方/方/m3/M3/Nm3/标方 ×1，升 ×0.001 |
| AREA | **平方米** | 平方米/平方/平米/㎡ ×1，平方英尺 ×0.0929 |

### 3.2 不可换算量纲 —— 只统一拼写，绝不跨概念合并

| 量纲 | 处理 | 理由 |
|---|---|---|
| SET | 套/组/SET/ST/台套 → `套`；付/副 → `副` | 一套含几件未知 |
| CONTAINER | 箱/盒/瓶/袋/桶/包/卷/罐/车/令 **各自保留** | **一箱装几个未知，箱 ≠ 个** |
| SERVICE | 项/次/份/笔/单/期/票 | 非实物计量 |
| BATCH | 批 | 批量未知 |
| POWER | 瓦/W/KVA | 功率不是能量，不能并入千瓦时 |
| TIME | 月 ×1，年 ×12 | |
| MONEY | 元 | **数量列填成了金额，`p ≡ 1`** |
| UNKNOWN | UNKNOWN / 无 / `-` | 单位缺失 |

### 3.3 需要复核的条目（已在表中标 medium/low）

| 单位 | 处理 | 疑虑 |
|---|---|---|
| `T`（11,392 条） | → 千克 ×1000 | 假定是 ton |
| `湿吨` / `干吨` | → 千克 ×1000 | 含水量口径不同，与干吨不可比 |
| `金属吨` | → 千克 ×1000 | 是"含金属量"，与毛重不是一回事 |
| `组`/`台套`/`ST` | → 套 | 语义相近但不完全等同 |
| `双` | → 个 ×2 | 一双 = 2 只 |
| `令` | 留作 CONTAINER | 实为 500 张，可换算但暂未做 |
| `KKWH` | → 千瓦时 ×1000 | K 前缀理解为"千" |

## 4 规整化效果

### 4.1 前后对照

| | buy 前 | buy 后 | sell 前 | sell 后 |
|---|---|---|---|---|
| 单位取值数 | 89,477 | **32** | 89,477 | **32** |
| 每产品单位数 中位数 | 49 | **15** | 35 | **13** |
| 每产品单位数 最大 | 34,803 | **31** | 3,171 | **31** |
| 主导单位占比 中位数 | 0.504 | **0.731** | 0.564 | **0.778** |
| 主导单位占比 **金额加权均值** | — | **0.836** | — | **0.860** |
| "只留主导单位"丢掉的金额 | 30.2% | **16.4%** | 27.0% | **14.0%** |
| 主导占比 <50% 的产品 | 49.4% | 18.2% | 40.4% | 14.5% |

落入 `OTHER` 的：buy 5.70% 的行、**1.15% 的金额**；sell 4.91% / 0.83%。长尾确实可以忽略。

### 4.2 单位映射已经做到头了

**主导量纲占比 0.842 ≈ 主导单位占比 0.836** —— 两者几乎相等，说明主导量纲内部已经只剩一个单位。**继续加同义词映射不会再有收益**，剩下的 16% 是真实的多单位申报。

### 4.3 一个反复出现的读数陷阱

不加权的计数指标会被长尾严重误导，本项目踩过两次：

- "80.7% 的产品有 >20 个单位" —— 被 89k 垃圾拼法撑虚
- "每产品跨 10 个量纲" —— 同样是不加权

真实情况看 `108030100`（铜）就清楚：20 个单位，但 **99.63% 的金额在千克上**，其余 19 个全是零头；其中 `个` 有 2,420 条记录却只占 0.10% 的金额。

> **结论：衡量单位混乱程度要用 `dom_share`（金额加权），不要用 `n_units` 或记录数。**

## 6 价格验证：规整化是否真的做对了

### 6.1 折算后的单价对得上真实市场价

买方侧金额最大的几个格子：

| 产品 | 单位 | p10 | **p50** | p90 | p90/p10 | 现实价格 |
|---|---|---|---|---|---|---|
| 铜 | 千克 | 36.74 | **51.99** | 72.94 | **2×** | ~50 元/kg ✓ |
| 原煤 | 千克 | 0.25 | **0.63** | 1.14 | 5× | ~630 元/吨 ✓ |
| 钢筋 | 千克 | 3.51 | **4.21** | 5.75 | **2×** | ~4,200 元/吨 ✓ |
| 供电 | 千瓦时 | 0.66 | **0.84** | 1.25 | **2×** | ~0.8 元/度 ✓ |
| 燃料油 | 千克 | 3.78 | **5.40** | 7.48 | 2× | ✓ |
| 初级形态塑料 | 千克 | 7.97 | **12.50** | 37.00 | 5× | ✓ |
| 手机 | 个 | 699 | **3,388** | 7,704 | 11× | ✓ |
| 电子计算机整机 | 个 | 1,235 | **4,150** | 8,899 | 7× | ✓ |

**这是最硬的验证**：吨/公斤/kg/KG 折算到千克之后，单价落在真实市场价上，离散度只有 2–5 倍。

### 6.2 但各量纲的可比性差别极大

只看占本产品金额 ≥5% 的格子（buy）：

| 量纲 | 占金额 | **p90/p10 中位** | p75/p25 | 判断 |
|---|---|---|---|---|
| ENERGY | 1.6% | **2.1×** | 1.4 | 干净 |
| VOLUME | 1.8% | **4.5×** | 2.2 | 干净 |
| CONTAINER | 2.8% | **10×** | 3.1 | 可用 |
| AREA | 0.5% | 12.5× | 3.7 | 可用 |
| **MASS** | **47.4%** | **14×** | 3.3 | **可用** |
| LENGTH | 1.3% | 40× | 6.2 | 偏差 |
| SERVICE | 1.8% | 75× | 8.4 | 差 |
| **COUNT** | **27.5%** | **269×** | 17.3 | **差** |
| **UNKNOWN** | **10.8%** | **327×** | 19.4 | **差** |
| **SET** | 3.3% | **348×** | 19.9 | 差 |

**根本原因：质量能自我归一，计数不能。** 一千克铜就是一千克铜；但"一个"可以是螺丝也可以是发动机。典型例子：

- `乘用车 / 个`：p10 = 124 元，p50 = 58,891，p90 = 234,823 → **1,897×**
- `机动车零配件 / 个`：**147×**
- `工程服务 / UNKNOWN`：**246×**

> **MASS + ENERGY + VOLUME + AREA + CONTAINER ≈ 54% 的金额可比；COUNT + SET + UNKNOWN ≈ 42% 不可比。**

## 7 ★ 附带发现：市场价的构造方式有系统性偏差

**这一条与单位无关，但直接打在项目核心变量上。**

`聚合价 = Σ金额 / Σ数量` 正是 `p_mkt` 与买卖方 **leave-one-out 均价**的构造方式。检查它落在企业价格分布的哪个位置：

| 聚合价的位置 | 格子数 | **占金额（buy）** | 占金额（sell） |
|---|---|---|---|
| **< p10** | 980 | **36.0%** | **26.8%** |
| p25–p75 | 3,642 | 31.5% | 43.1% |
| > p90 | 66 | 0.3% | 0.2% |

**超过三分之一的金额上，`Σ金额/Σ数量` 算出的"市场价"低于该市场 90% 企业的实际成交价。**

| 产品/单位 | 聚合价 | 中位价 | 差距 |
|---|---|---|---|
| 热轧薄板/千克 | **0.01** | 4.40 | **440×** |
| 零配件/个 | 10.40 | 164.51 | 16× |
| 乘用车/个 | 7,369 | 58,891 | 8× |
| 手机/个 | 1,089 | 3,388 | 3× |
| 供电/千瓦时 | 0.31 | 0.84 | 2.7× |

**原因**：极端数量未被清理。`01_inspect_raw` 中 `数量合计` 的最大值是 **7.63e15**，一条这样的记录就能把整个市场的 Σ数量 拉爆。02 只删了 `qty ≤ 0`，没有设上界。

**影响范围**：`p_buy`（DV）、`p_mkt`、买方 LOO、卖方 LOO、`mkt_qty` —— 全部由 Σ/Σ 构造。

## 8 买卖单位一致性（任务书决策点 2）

- (企业,产品) 对：只买 4,564,881 ／ 只卖 670,250 ／ **既买又卖 529,990（外包候选）**
- 买卖主导单位一致：按对数 **41.9%**，按外包额加权 **69.4%**
- 最常见的不一致：`台→个`、`套→个`、`UNKNOWN→吨`、`吨→公斤`、`箱→个`、`吨→千克`、`只→个`

**结论：外包识别应在 9 位产品层忽略单位。** 因为外包额 `min(买,卖)` 用的是**金额（元）**，量纲本来就统一，跨单位不构成任何问题；单位只影响单价和数量。若反过来要求单位一致才算外包，会砍掉一半以上的外包样本。

## 9 已知问题与 limitation

1. **COUNT / SET / UNKNOWN 共 42% 的金额，单价不可比**（p90/p10 269–348×）。这是 9 位产品码内部的真实异质性，不是单位问题，加映射解决不了。
2. **`UNKNOWN` 占 buy 金额 11%**，规整后升至第三位。其中相当一部分是服务类产品的正常状态（`305010000 工程服务` 有 80.4% 的金额是 UNKNOWN）。
3. **`元` 作为"单位"**（buy 20,175 行 / sell 1,481 行）：数量列填的是金额，`p ≡ 1`，纯噪音，建议直接剔除。
4. **SERVICE / BATCH 类单价无物理含义**（合计 buy 2.5%）："1 批"可以是任何数量。
5. **Σ金额/Σ数量 的市场价有系统性向下偏差**（见第 7 节）—— 未解决，需要 winsorize。
6. **9 位产品码本身粒度偏粗**。参照的 `IO_Table/io_repro/02_cleaning_pipeline.do` 用的是 15 位。本项目受 `bianma.dta` 只有 9 位码的约束，暂按既定口径不改。
7. 映射表中 7 条 medium/low 置信度条目待复核（见 3.3）。
